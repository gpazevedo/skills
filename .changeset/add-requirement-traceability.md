Add the `requirement-traceability` skill (engineering bucket, model-invoked). It is an opt-in convention that ties each requirement in a spec to a test and makes "every requirement has a test" checkable. Run `/requirement-traceability` once after `/to-tickets` and it annotates what `to-spec` and `to-tickets` wrote: requirement IDs (`CPN-3:`) on the user stories, a seam table, and a `Covers:` line on each ticket, then runs a structural check (every ID on exactly one ticket, none undefined) and fixes violations itself, asking only about an ID no ticket builds. A spec that carries IDs turns the rest on; a spec without them changes nothing. The skill defines the requirement ID (always colon-anchored, so `CPN-1` never matches `CPN-10`), a seam table, an ID-prefixed test tag, a per-issue `Covers:` line, and a coverage gap check that reports untested IDs, tagged tests with an undefined ID, and tests with no ID.

Only two existing skills change, each by one guarded line that does nothing when the spec has no IDs: `tdd` tags each test with its ID, and `implement` runs the gap check (and the Judgement pass) before review, over every ID in the spec on the last open ticket. `to-spec`, `to-tickets` and `code-review` are unchanged. Docs pages, `ask-matt` and `CONTEXT.md` are re-synced, and the `grill-with-docs` page now names traceability as the mitigation for the spec-to-test half of its "no ledger" complaint.

An optional Judgement pass (`judge.mjs`) asks Jev, TypeSafe's System One model, whether the tests tagged with each requirement check all of it, and sorts requirements into ok, flag and uncertain. For a flagged requirement the agent adds tests for the unchecked part and re-runs the pass, at most 3 rounds before asking the user. It runs only when `TYPESAFE_API_KEY` is set and `docs/agents/traceability.md` has a `Judgement: jev` line, and it never fails a build (ADR 0003). Each line of `docs/agents/traceability.md` is now independently optional.

The Judgement pass sends each tagged test from its tag to its end (Python by indentation, JS/TS and Go by the parenthesis enclosing the tag), so helpers and neighbouring tests stay out of the request; a test longer than 200 lines is cut there and its file marked `(cut)` so the agent reads it whole. `node --test scripts/test-tags.mjs` holds that in place.

The gap check is `check.mjs` (Node, no packages), sharing its rules with `judge.mjs` through `tags.mjs` (ADR 0004). It exits 1 on an untested ID, takes a ticket's `Covers:` IDs as arguments to narrow the check, and recognises JS/TS, pytest and Go tests without configuration. A quoted ID counts only where a test name sits, so an ID inside an assertion value is not coverage. It ignores commented-out and skipped tests, including a skip whose test name wraps onto the next line and a Python test under `@pytest.mark.skip` or `@unittest.skip`, so a requirement whose only test is switched off is reported untested instead of covered. The "no ID" warning reads a pytest tag from the docstring and a wrapped JS name from the next line. `scripts/test-traceability-check.sh` runs `check.mjs` and the `Covers:` structural check against a fixture and holds both in place.
